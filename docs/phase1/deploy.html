Deployment Philosophy

You're in early stage — a handful of beta users, proving the product works. The goal: get it online for real users as cheaply as possible without sacrificing reliability. You can always scale later.

Key principles for this stage:

  • Use free tiers aggressively — most cloud providers offer generous free tiers
  • Managed databases — don't waste time on DB ops; use hosted services
  • Single VPS — one cheap server runs everything until you need to scale
  • Pay only for what you can't get free — compute and AI API calls

Step-by-Step Deployment

1

Set Up Managed Databases (Free Tiers)

A) Neon PostgreSQL

  1. Sign up at neon.tech (GitHub login works)
  2. Create a new project named creator-os
  3. Copy the connection string — it looks like: postgresql://user:pass@ep-xxx.region.aws.neon.tech/creator_os?sslmode=require
  4. Enable the pgvector extension: go to SQL Editor and run CREATE EXTENSION vector;
  5. Note: For asyncpg, change the scheme to postgresql+asyncpg://

B) Upstash Redis

  1. Sign up at upstash.com
  2. Create a new Redis database in the region closest to your VPS
  3. Copy the Redis URL — it looks like: rediss://default:xxx@region.upstash.io:6379
  4. Create a second database for Celery broker (or use database index 1 of the same instance)

C) Neo4j Aura Free

  1. Sign up at neo4j.com/cloud/aura-free
  2. Create a free instance — save the password (shown only once!)
  3. Note the connection URI: neo4j+s://xxx.databases.neo4j.io
  4. Load the initial schema: open the Neo4j Browser and paste contents of infrastructure/docker/neo4j/init.cypher
2

Provision the VPS (Hetzner)

  1. Sign up at hetzner.com/cloud
  2. Create a new server:
    • Location: Closest to your users (e.g., Ashburn for US)
    • Image: Ubuntu 24.04
    • Type: CX22 (2 vCPU, 4 GB RAM) — $4.50/mo
    • SSH Key: Add your public key
  3. Note the server IP address
SSH into your server 
ssh root@YOUR_SERVER_IP
3

Set Up the Server

Server Setup (run on VPS) 
# Update system
apt update && apt upgrade -y

# Install Python 3.12, pip, venv
apt install -y python3.12 python3.12-venv python3-pip

# Install Git
apt install -y git

# Install Caddy (reverse proxy with auto HTTPS)
apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | tee /etc/apt/sources.list.d/caddy-stable.list
apt update && apt install -y caddy

# Create app user (don't run app as root)
useradd -m -s /bin/bash creator
su - creator

Deploy the Backend Code

As 'creator' user on VPS

Create Systemd Services (Auto-Start on Boot)

Create service files so everything starts automatically and restarts on crash:

A) FastAPI Backend

/etc/systemd/system/creator-api.service 
sudo nano /etc/systemd/system/creator-api.service

[Unit]
Description=Creator OS API
After=network.target

[Service]
Type=exec
User=creator
Group=creator
WorkingDirectory=/home/creator/creator-os/backend
EnvironmentFile=/home/creator/creator-os/.env
ExecStart=/home/creator/creator-os/backend/.venv/bin/gunicorn \
    app.main:app \
    --workers 2 \
    --worker-class uvicorn.workers.UvicornWorker \
    --bind 127.0.0.1:8000 \
    --timeout 120
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target

Configure Caddy (Reverse Proxy + HTTPS)

Caddy automatically provisions and renews SSL certificates from Let's Encrypt:

/etc/caddy/Caddyfile 
sudo nano /etc/caddy/Caddyfile

api.yourdomain.com {
    reverse_proxy localhost:8000

    # WebSocket support
    @websocket {
        header Connection *Upgrade*
        header Upgrade    websocket
    }
    reverse_proxy @websocket localhost:8000

    # Security headers
    header {
        X-Content-Type-Options nosniff
        X-Frame-Options DENY
        Referrer-Policy strict-origin-when-cross-origin
    }
}

# Reload Caddy:
Terminal 
sudo systemctl restart caddy
sudo systemctl status caddy

Deploy Frontend to Vercel (Free)

  1. Push your code to GitHub
  2. Go to vercel.com and import your repository
  3. Set the Root Directory to frontend
  4. Add environment variables in Vercel's dashboard:
    • NEXT_PUBLIC_API_URL = https://api.yourdomain.com
    • NEXTAUTH_URL = https://yourdomain.com
    • NEXTAUTH_SECRET = (same as .env)
    • GOOGLE_CLIENT_ID = (your YouTube OAuth client ID)
    • GOOGLE_CLIENT_SECRET = (your YouTube OAuth client secret)
  5. Click Deploy — Vercel builds and hosts automatically
  6. Add your custom domain in Vercel's domain settings
Auto-deploy: Every time you push to your main branch, Vercel automatically rebuilds and deploys the frontend. Zero effort.

Deploying Updates

When you push new code:

Frontend (Automatic)

Push to main — Vercel deploys automatically. Done.

Backend (Manual, ~30 seconds)

SSH into VPS 
ssh root@YOUR_SERVER_IP
su - creator
cd ~/creator-os

# Pull latest code
git pull origin main

# Install any new dependencies
cd backend && source .venv/bin/activate
pip install -e ".[dev]"

# Run new migrations (if any)
alembic upgrade head

# Restart services
sudo systemctl restart creator-api creator-celery creator-beat
Automate this! You can set up a simple GitHub webhook or use GitHub Actions to SSH into your VPS and run these commands automatically on push. But for a few users, manual deploy is fine.

Neon handles backups automatically with point-in-time recovery on the free tier. No action needed.

ChromaDB (VPS)

Data lives in ~/creator-os/chroma_data/. Set up a cron job to tar and upload to cloud storage weekly.

Code

It's in Git. Push regularly. That's your backup.

Simple ChromaDB Backup Script

backup-chroma.sh (cron weekly) 
#!/bin/bash
DATE=$(date +%Y%m%d)
tar -czf /home/creator/backups/chroma-$DATE.tar.gz /home/creator/creator-os/chroma_data
# Keep only last 4 backups

# Add to crontab: crontab -e
# 0 4 * * 0 /home/creator/backup-chroma.sh

When to Scale

This setup comfortably handles 1–10 active users. Here's when and how to scale:

SignalBottleneckActionNew Cost
API response > 2s VPS CPU/RAM Upgrade to CX32 (4 vCPU, 8 GB) $8/mo
Neon hits 0.5 GB DB storage Upgrade Neon to Launch ($19/mo) or self-host on VPS $0–$19/mo
Upstash 10K cmds/day limit Redis commands Upgrade to Pay-as-you-go ($0.2/100K cmds) ~$2/mo
Neo4j Aura 200K node limit Graph size Upgrade to Aura Pro ($65/mo) or self-host on VPS $0–$65/mo
10+ concurrent agent runs Celery workers Increase concurrency or add a second VPS for workers $4.50/mo
50+ users Everything Time to containerize and use a proper orchestrator (K8s, Fly.io) $50–$150/mo

Production Security Checklist

  • SSH key only — Disable password SSH: PasswordAuthentication no in /etc/ssh/sshd_config
  • Firewall — Only allow ports 22 (SSH), 80, 443: ufw allow 22,80,443/tcp && ufw enable
  • No root login — App runs as creator user, not root
  • HTTPS everywhere — Caddy auto-provisions SSL certificates
  • Secrets in .env — Never commit .env to Git (already in .gitignore)
  • Update regularly — apt update && apt upgrade weekly
  • Set APP_ENV=production — Disables debug mode and detailed error messages
  • CORS locked — Backend only accepts requests from your frontend domain
  • Rate limiting active — Already built into the app via Redis
Quick security setup 
# Set up firewall
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable

# Disable root SSH login
sudo sed -i 's/PermitRootLogin yes/PermitRootLogin no/' /etc/ssh/sshd_config
sudo systemctl restart sshd

# Auto security updates
sudo apt install unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades
